# التكنولوجيا المقترحة والأمان — منظومة الصفوة

> **الحالة:** توصية معمارية (مدخل لـ `/speckit-plan` بعد اعتماد الـ spec) · **التاريخ:** 3 أكتوبر 2026
> **السياق:** بيانات حساسة جدًا (أرقام قومية، صور بطاقات وعقود، شهادات ميلاد أطفال، حسابات مالية)، فرعان و5–20 موظفًا، موقع عام للعملاء، وسجل نشاط لكل عملية.

## 1. القرار باختصار

| الطبقة | الاختيار | السبب الرئيسي |
|---|---|---|
| الخادم (API) | **ASP.NET Core 10 (LTS)** — Clean Architecture + CQRS | خبرة الفريق الحالية (Segelly)، أدوات أمان مدمجة ناضجة، نوع `decimal` للمال، دعم طويل حتى نوفمبر 2028 |
| قاعدة البيانات | **PostgreSQL 17/18** + EF Core 10 | Row-Level Security لعزل الفروع، triggers تمنع تعديل السجلات، `pgaudit`، نسخ احتياطي لحظي (PITR) |
| لوحة الموظفين | **React 19 + TypeScript + Vite** (SPA بنمط BFF) | امتداد مباشر للديمو الحالي، أفضل نظام بيئي لجداول ونماذج كثيفة وRTL والطباعة |
| الموقع العام | موقع منفصل خفيف (Astro أو React مُصدَّر static) + API عام ضيق | عزل سطح الهجوم العام عن نظام الموظفين، SEO محلي |
| تخزين المستندات | تخزين كائنات متوافق مع S3 (MinIO) مشفّر، داخل مصر | ملفات كبيرة خارج قاعدة البيانات، تشفير لكل ملف |
| الاستضافة | **مركز بيانات/سحابة داخل مصر** | قانون حماية البيانات 151/2020 يقيّد نقل البيانات للخارج |
| تطبيق موبايل للعملاء (لاحقًا) | **Flutter** | خبرة الفريق؛ مناسب للموبايل وليس للوحة الموظفين |

## 2. لماذا هذه الاختيارات (والبدائل المرفوضة)

### 2.1 الخادم

**ASP.NET Core 10** يوفر بدون مكتبات خارجية: ASP.NET Core Identity (تجزئة كلمات مرور، قفل الحساب، TOTP، و**Passkeys** في الإصدار 10)، Data Protection API لإدارة مفاتيح التشفير، Antiforgery ضد CSRF، Rate Limiting مدمج، Authorization Policies قائمة على الموارد. والفريق يعرف نفس المعمارية من Segelly (Clean Architecture، MediatR، FluentValidation، ProblemDetails)، فنقلل وقت التعلم والأخطاء.

| بديل | لماذا لم يُختر |
|---|---|
| Node.js / NestJS | ممتاز، لكن الأمان يعتمد على مكتبات طرف ثالث أكثر، ومخاطر سلسلة التوريد في npm أعلى (هجمات 2025 على حزم شهيرة)، والفريق أقل خبرة |
| Laravel / Django | خيارات قوية، لكن تعني لغة ونظامًا جديدًا للفريق دون ميزة حاسمة |
| Supabase / Firebase | خدمات مُدارة خارج مصر غالبًا (مشكلة إقامة البيانات)، وقواعد الصلاحيات الحرجة تصبح في إعدادات المنصة بدل الكود المُختبر |

> ملاحظة ترخيص: MediatR أصبحت تجارية لنسخها الحديثة مع نسخة مجانية للشركات الصغيرة؛ نتحقق من الشروط أو نستخدم بديلًا مفتوح المصدر (مثل source-generated mediator).

### 2.2 الواجهة

**React + TypeScript** مع: TanStack Router (مسارات مكتوبة الأنواع) + TanStack Query (بيانات الخادم) + React Hook Form + Zod (نماذج وتحقق) + Tailwind CSS 4 بنفس design tokens الديمو + مكوّنات Radix (إتاحة ووصول جاهزة، تدعم RTL) + i18next (العربية أولًا مع تجهيز للإنجليزية).

**لماذا ليس Flutter Web للوحة الموظفين؟** الرسم على Canvas يُضعف: تحديد النص والنسخ، البحث داخل الصفحة، قارئات الشاشة، الطباعة الدقيقة للإيصالات، حجم التحميل، وتطبيق سياسة CSP صارمة. لوحة بيانات كثيفة تُستخدم 8 ساعات يوميًا على كمبيوترات مكتب تناسبها تقنيات الويب الأصلية. Flutter يبقى الأنسب لتطبيق موبايل للعملاء لاحقًا.

### 2.3 نمط BFF (Backend-for-Frontend)

الواجهة تُقدَّم من نفس نطاق الـ API، والجلسة **كوكي `HttpOnly; Secure; SameSite=Strict`** يصدرها الخادم. **لا توكنات في `localStorage`** ولا في JavaScript إطلاقًا — فأي ثغرة XSS لا تستطيع سرقة الجلسة.

## 3. المعمارية

```
                    الإنترنت
                       │
        ┌──────────────┴──────────────┐
        │  WAF + CDN (حماية DDoS/بوتات)│
        └──────┬───────────────┬──────┘
               │               │
     الموقع العام (static)   API عام ضيق: تقديم طلب / تتبع بـ OTP
                               │  (rate-limit صارم، بدون أي بيانات داخلية)
                               │
  الموظفون ── Zero-Trust/VPN ──┤  (Cloudflare Access أو WireGuard + IP الفروع)
                               │
                 ┌─────────────┴─────────────┐
                 │  Staff BFF + API (.NET 10) │── Vault/KMS (مفاتيح التشفير)
                 └──┬──────────┬──────────┬───┘
                    │          │          │
            PostgreSQL     MinIO (مستندات   ClamAV
            (شبكة خاصة)    مشفرة)           (فحص الملفات)
                    │
         نسخ احتياطي مشفّر + نسخة غير قابلة للتعديل (WORM) في موقع ثانٍ داخل مصر
```

**مبدأ أساسي:** لوحة الموظفين **غير مكشوفة للإنترنت العام**؛ الوصول فقط عبر Zero-Trust/VPN مع MFA. الموقع العام يتعامل مع API منفصل لا يملك صلاحية قراءة إلا "عرض التتبع" المقيّد.

### 3.1 هيكل الكود (Clean Architecture)

```
src/
  Safwa.Domain          كيانات وقواعد العمل (آلة حالات المعاملة، القيد المحاسبي) — بلا أي اعتماديات
  Safwa.Application     أوامر/استعلامات لكل حالة استخدام + التحقق + فحص الصلاحية داخل كل Handler
  Safwa.Infrastructure  EF Core، التشفير، MinIO، SMS، الإيصال الإلكتروني
  Safwa.Api             BFF، المصادقة، الـ pipeline الأمني
  Safwa.PublicApi       واجهة الموقع العام (مشروع ونشر منفصلان)
```

### 3.2 نموذج البيانات (الجداول الأساسية)

`branches` · `users` / `user_credentials` / `user_mfa` / `sessions` · `roles` / `permissions` · `clients` (حقول مشفرة + blind index) · `client_consents` · `powers_of_attorney` · `service_types` / `service_versions` / `service_steps` / `service_documents` · `requests` (مع `service_version_id`) · `request_steps` · `request_events` (public/internal) · `documents` / `document_custody` (الأصول ورد الأصل) · `payments` / `receipts` (ترقيم لكل فرع وسنة) · `disbursements` (بإيصال حكومي) · `cash_sessions` (فتح/إقفال الخزينة) · `ledger_entries` / `ledger_lines` · `audit_events` (append-only) · `data_subject_requests`.

الديمو الحالي يطبّق نفس الأسماء والقواعد بشكل مصغّر (`src/data/types.ts` و`src/data/engine.ts`).

## 4. الأمان — طبقة بطبقة

المرجع: **OWASP ASVS 5.0 المستوى 2** للنظام كله، و**المستوى 3** لأجزاء المصادقة والمالية والسجل. مع مراجعة OWASP Top 10 (إصدار 2025) في كل Pull Request.

### 4.1 الهوية والدخول

- **لا تسجيل ذاتي.** المدير العام يضيف الموظف ← رابط دعوة لمرة واحدة صالح 24 ساعة لتعيين كلمة المرور وتفعيل MFA.
- كلمة مرور ≥ 12 حرفًا، فحص ضد قوائم كلمات المرور المسربة، بدون قواعد تعقيد مُرهقة (NIST SP 800-63B). التجزئة بـ **Argon2id** (أو PBKDF2 الافتراضي في Identity بعدد تكرارات مرتفع).
- **MFA إلزامي للجميع**: Passkeys (الأفضل) أو تطبيق مصادقة TOTP. **لا SMS كعامل ثانٍ للموظفين** (عرضة لتبديل الشريحة).
- قفل بعد 5 محاولات فاشلة مع تأخير متزايد، ورسالة خطأ موحدة (لا تكشف وجود البريد).
- جلسة: خمول 15 دقيقة، حد أقصى 10 ساعات (يوم عمل)، قائمة أجهزة نشطة مع إنهاء عن بعد، إعادة إصدار الجلسة بعد الدخول.
- **إعادة مصادقة (step-up)** قبل العمليات الحساسة: إلغاء إيصال، تصدير بيانات، تعديل صلاحيات، كشف رقم قومي بالجملة.
- تنبيه للمدير عند: دخول خارج مواعيد العمل، دخول من جهاز جديد، محاولات فاشلة متكررة.

### 4.2 الصلاحيات

- RBAC (مدير عام، مدير فرع، موظف خدمة، محاسب/خزينة، مراجع للقراءة فقط) + **قيود حسب الفرع والإسناد** (ABAC).
- **الفحص داخل كل Handler** وليس فقط بإخفاء الأزرار (الديمو الجديد يطبق ذلك في `engine.ts`).
- **PostgreSQL Row-Level Security** على `branch_id` كخط دفاع ثانٍ لو أخطأ الكود.
- **فصل المهام (Maker–Checker):** لا يلغي أحد إيصالًا أصدره بنفسه؛ الخصومات فوق حد معين واسترداد الأمانات تحتاج موافقة مدير؛ تعديل الصلاحيات يُسجَّل ويُبلَّغ به المدير العام.
- أقل صلاحية: المحاسب لا يعدّل خطوات المعاملات، والموظف لا يرى تقارير الفروع الأخرى.

### 4.3 حماية البيانات

| الطبقة | الإجراء |
|---|---|
| أثناء النقل | TLS 1.3 فقط، HSTS مع preload، شهادات تتجدد آليًا |
| على القرص | تشفير الأقراص (LUKS/BitLocker) لكل الخوادم والنسخ الاحتياطية |
| على مستوى الحقل | **تشفير مغلّف (Envelope) بـ AES-256-GCM** للرقم القومي والموبايل والعنوان؛ مفتاح بيانات لكل سجل ومفتاح رئيسي في **Vault/HSM** لا يخرج منه |
| البحث في الحقول المشفرة | **Blind index** بـ HMAC-SHA256 بمفتاح منفصل (بحث بالمطابقة الكاملة للرقم القومي/الموبايل) |
| المستندات | مفتاح لكل ملف، تخزين في MinIO خاص، تُعرض فقط عبر الـ API بعد فحص الصلاحية، روابط مؤقتة بدقائق، **علامة مائية** باسم الموظف ووقت العرض |
| الرفع | فحص نوع الملف بالمحتوى (magic bytes) وليس الامتداد، حد للحجم، **فحص ClamAV**، إزالة البيانات الوصفية من الصور |
| العرض | الرقم القومي **مُقنَّع افتراضيًا** ويُكشف بصلاحية مع تسجيل (مطبق في الديمو) |
| التصدير | بصلاحية خاصة، بدون أرقام قومية افتراضيًا، مُسجَّل، مع حماية CSV من حقن المعادلات (مطبق في الديمو) |
| السجلات التقنية (logs) | **ممنوع أي بيانات شخصية** في logs التطبيق؛ اختبار آلي يفحص ذلك |
| الاحتفاظ والمحو | سياسة مدد احتفاظ لكل نوع بيانات؛ التجهيل بدل الحذف للسجلات المالية بعد انتهاء المدة القانونية |

### 4.4 سجل النشاط (مين عمل إيه وإمتى)

**المطلوب من المكتب نصًا: "log لكل حاجة بتتم ومين الموظف اللي عملها وعملها إمتى".** التصميم:

1. **ماذا يُسجَّل:** كل عملية كتابة (إنشاء/تعديل/حالة/دفع/إلغاء/رفع/حذف/صلاحيات/إعدادات) **وكل اطلاع على بيانات حساسة** (فتح ملف عميل، كشف رقم قومي، عرض مستند، طباعة إيصال، تصدير)، وكل أحداث الدخول.
2. **كل سجل يحتوي:** رقم تسلسلي، الوقت من ساعة الخادم (UTC مع NTP)، المستخدم ودوره وفرعه، العملية، الكيان ورقمه، ملخص التغيير (قيمة قبل/بعد للحقول غير الحساسة، واسم الحقل فقط للحساسة)، عنوان IP والجهاز ومعرّف الجلسة، معرّف الطلب للتتبع، والسبب للعمليات الاستثنائية.
3. **غير قابل للتعديل:** جدول **append-only**؛ مستخدم قاعدة البيانات الخاص بالتطبيق له صلاحية `INSERT/SELECT` فقط؛ triggers ترفض `UPDATE/DELETE/TRUNCATE`؛ والجدول ليس ملكًا لمستخدم التطبيق.
4. **كشف التلاعب:** كل سجل يحمل بصمة SHA-256 للسجل السابق (سلسلة)، وبصمة "رأس السلسلة" تُصدَّر يوميًا موقّعة إلى تخزين WORM خارجي — أي تعديل أو حذف يكسر السلسلة ويُكتشف (مطبّق ومُجرَّب في الديمو: شاشة "سجل النشاط" ← "التحقق من سلامة السجل"، مع زر محاكاة تلاعب).
5. **على مستوى قاعدة البيانات:** `pgaudit` لتسجيل أي وصول مباشر لقاعدة البيانات خارج التطبيق (مثل مدير النظام).
6. **الاستخدام:** شاشة بحث وتصفية حسب الموظف/العملية/المعاملة/التاريخ، تصدير موقّع للمراجعة، وتنبيهات آلية (تصدير كبير، كشف أرقام قومية كثيرة في وقت قصير، إلغاء إيصالات متكرر، نشاط ليلي).
7. **الاحتفاظ:** سجلات النشاط المالية مع السجلات المالية (5 سنوات على الأقل)، وسجلات الدخول 180 يومًا على الأقل.

### 4.5 النزاهة المالية

- **قيد مزدوج** (Double-entry): كل عملية مالية قيد متوازن؛ الحسابات تفصل **إيراد الأتعاب** عن **التزام أمانات العملاء** عن **عُهد الموظفين**.
- **لا تعديل ولا حذف** لأي قيد أو إيصال؛ التصحيح بقيد عكسي، والإلغاء بسبب ومن مدير آخر (مطبق في الديمو).
- **ترقيم إيصالات متسلسل بلا فجوات** لكل فرع وسنة، يُولَّد داخل transaction في قاعدة البيانات.
- **جلسات خزينة:** فتح وإقفال يومي لكل أمين خزينة، مطابقة النقدية الفعلية، تسجيل الفروقات بموافقة.
- **لا صرف أمانة** بدون رقم الإيصال الحكومي وصورته (مطبق في الديمو).
- **أنواع رقمية:** `decimal(18,2)` — ممنوع `float` للمال.
- **تكامل مصلحة الضرائب:** وحدة مستقلة للإيصال الإلكتروني (B2C) والفاتورة الإلكترونية (B2B) عند انطباقها، مع مفاتيح التوقيع في HSM/توكن آمن، وحفظ الـ UUID وطباعة الـ QR على الإيصال.

### 4.6 أمان التطبيق

- **CSP صارمة** (nonce، بدون `unsafe-inline` للسكربتات، بدون سكربتات طرف ثالث في لوحة الموظفين)، `frame-ancestors 'none'`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy` (الكاميرا فقط لصفحة المسح).
- **الخطوط والأصول مستضافة ذاتيًا** (لا Google Fonts ولا CDN في لوحة الموظفين — مطبق في الديمو عبر `@fontsource`).
- التحقق من المدخلات في الخادم (FluentValidation) حتى لو تحققت الواجهة؛ استعلامات EF Core بارامترية؛ React يهرّب المخرجات ولا `dangerouslySetInnerHTML`.
- Antiforgery + `SameSite=Strict`، CORS مغلق، Rate limiting (الدخول، OTP، التتبع العام، التصدير).
- **التتبع العام:** رقم المعاملة + الموبايل ثم **OTP** صالح 5 دقائق و3 محاولات، رسالة خطأ موحدة لا تكشف وجود المعاملة، والعرض **لرسائل العميل فقط** (مطبق في الديمو).
- أرقام مرجعية للمعاملات غير قابلة للتخمين في الإنتاج (أو تسلسلية مع OTP كما هو مطبق).
- **أسرار** في Vault فقط — ممنوع في الكود أو ملفات `.env` داخل المستودع؛ فحص آلي للأسرار في CI.

### 4.7 سلسلة التوريد والتطوير الآمن

- `npm ci` / `dotnet restore --locked-mode` من ملفات القفل فقط؛ **تأخير قبول الإصدارات الجديدة** للحزم (مثلًا 7 أيام) لتجنب الحزم المخترقة حديثًا؛ منع سكربتات التثبيت إلا لقائمة معتمدة.
- Dependabot/Renovate، `npm audit` و`dotnet list package --vulnerable` في CI، تحليل ساكن (CodeQL/Semgrep)، فحص الحاويات (Trivy)، فحص ديناميكي (OWASP ZAP) على بيئة الاختبار، **SBOM** لكل إصدار.
- حماية الفرع الرئيسي، مراجعة إلزامية لكل PR، ومراجعتان لأي تغيير في المصادقة/الصلاحيات/المالية/السجل، توقيع الـ commits.
- **اختبار اختراق مستقل** قبل الإطلاق وبعد أي تغيير كبير.

### 4.8 البنية التحتية والتشغيل

- **الاستضافة داخل مصر** (مركز بيانات أو سحابة محلية بشهادات مثل ISO 27001)، مع اتفاقية معالجة بيانات مع المزوّد. أي خدمة خارجية تلمس بيانات العملاء (SMS، واتساب، بريد) تُراجع من منظور النقل للخارج وتُقلَّل البيانات المرسلة (لا أرقام قومية في الرسائل).
- حاويات Docker، Reverse proxy (YARP/Caddy) بـ TLS، قاعدة البيانات في شبكة خاصة بلا منفذ عام، دخول الإدارة عبر Bastion/VPN مع MFA، تقوية الخوادم وفق CIS Benchmarks، تحديثات أمنية آلية.
- **النسخ الاحتياطي (3-2-1):** WAL archiving مع استعادة لنقطة زمنية (pgBackRest)، نسخة يومية مشفرة في موقع ثانٍ داخل مصر، نسخة غير قابلة للتعديل (WORM) ضد الفدية، **اختبار استعادة كل 3 شهور**. الأهداف: فقد بيانات ≤ 15 دقيقة، عودة الخدمة ≤ 4 ساعات.
- مراقبة: OpenTelemetry → Grafana/Loki/Prometheus (أو Seq) بدون بيانات شخصية، تنبيهات على الأعطال والأنماط المشبوهة.
- خطة استجابة للحوادث: من يتصرف، عزل، تقييم، **إخطار مركز حماية البيانات في المدة القانونية**، إخطار المتضررين، ودروس مستفادة.

### 4.9 أمان المكتب نفسه (لا يقل أهمية)

كمبيوترات بحسابات مستخدم عادية (ليست Administrator) وتشفير BitLocker وقفل تلقائي ومضاد فيروسات/EDR، منع الحسابات المشتركة، مدير كلمات مرور، تقييد وحدات USB، تدريب دوري ضد التصيد، **إقرار سرية** لكل موظف، خزانة مغلقة للأصول، **فرّامة** للنسخ الزائدة، كاميرا على الخزينة، وعدم تبادل صور البطاقات عبر واتساب الشخصي (النظام يوفر رفعًا آمنًا بديلًا).

### 4.10 الماسح الضوئي

المتصفح لا يصل مباشرة لتعريفات TWAIN/WIA. الحلول: برنامج وسيط محلي على أجهزة الفروع (مثل Dynamic Web TWAIN — تجاري، أو أداة مسح مفتوحة المصدر مع رفع لمجلد مراقب)، أو ماسحات تدعم الحفظ إلى مجلد شبكي/بريد داخلي. البديل الفوري المطبق في الديمو: **التصوير بالكاميرا مع فلتر تحسين المستند**.
